Complex queries, one operator at a time.

database-helpers-go turns a relational or Elasticsearch query into a pipeline of small operators. Filtering, search, ordering and pagination are read from the request, checked against the fields you allow, and applied in order.

go get github.com/pixie-sh/database-helpers-go

Go 1.25+, built on GORM. MIT licensed. The full reference is in the README.

The problem

Every list endpoint grows the same pile of ifs.

A tenant filter, then free-text search, then sorting, then pagination. Each one wraps the query builder in conditions, and each endpoint writes them again, slightly differently.

By hand

q := db.Model(&User{}).Where("tenant_id = ?", tenantID)

if s := params.Get("q"); s != "" {
    q = q.Where("name LIKE ?", "%"+s+"%")
}

switch params.Get("sort_by") {
case "created_at":
    q = q.Order("created_at ASC")
case "-created_at", "":
    q = q.Order("created_at DESC")
default:
    return nil, errBadSort
}

page, perPage := parsePaging(params) // and its limits
var total int64
q.Count(&total)
q.Limit(perPage).Offset((page - 1) * perPage).Find(&users)

Written again for orders, invoices and every other list.

As a pipeline

pipeline.NewPipeline(log).
    AddOperator(
        operators.NewHardWhereOperator("tenant_id = ?", tenantID),
        operators.NewGlobalSearchOperator(params, "q",
            models.SearchableProperty{Field: "name", Type: "text",
                Comparison: "LIKE", LikeBefore: true, LikeAfter: true},
        ),
        operators.NewOrderByOperator(params, true, []string{"-created_at"},
            models.SearchableProperty{Field: "created_at", Type: "date"},
        ),
        operators.NewPaginateOperator(params, &users, 10, 25, 50),
    ).
    ExecWithPassable(ctx, operators.NewResult(db.Model(&User{})))

Four operators, in the order they apply. The next endpoint reuses them.

One operator, one concern

Operators are small, ordered and testable on their own.

Driven by the request

Search, order and pagination read the query string and accept only the fields you list.

Two back ends, one shape

The same pipeline builds a GORM query or an Elasticsearch _search body.

Elasticsearch

Search bodies without hand-written JSON.

Elasticsearch operators add clauses to a builder: filters, nested bool queries, geo distance, scoring scripts and pagination. The result is a plain request you can send with the bundled repository or any client.

result, err := pipeline.NewPipeline(log).
    AddOperator(
        elastic.NewSourceOperator("id", "title", "status"),
        elastic.NewFilterOperator(elastic.Term("status", "live")),
        // online deals, or physical deals within 250 km
        elastic.NewFilterOperator(elastic.BoolShould(1,
            elastic.Term("deal_type", "online"),
            elastic.BoolFilter(
                elastic.Term("deal_type", "physical"),
                elastic.GeoDistance("locations.coords", "250km", 52.3676, 4.9041),
            ),
        )),
        elastic.NewMustNotOperator(elastic.IDs("hidden_deal_id")),
        elastic.NewShouldOperator(elastic.MultiMatch("eco laundry", "title^3", "description")),
        elastic.NewMinimumShouldMatchOperator(1),
        elastic.NewFromSizePaginationOperator(0, 30),
    ).
    ExecWithPassable(ctx, operators.NewResult(elastic.NewBuilder("deals")))

request := result.GetPassable().(*elastic.Builder).SearchRequest()

repo := database.NewElasticRepository(database.ElasticConfiguration{
    BaseURL: "https://search.internal:9200",
    Index:   "deals",
})
response, err := repo.Search(ctx, request)

Connections, repositories and migrations.

Migrations

NewMigrator runs ordered migrations.

Elasticsearch repository

ElasticRepository covers search, index creation, bulk indexing and cursor helpers.

type UserRepository struct {
    database.Repository[UserRepository]
}

func NewUserRepository(db *database.DB) UserRepository {
    return UserRepository{database.NewRepository(db, NewUserRepository)}
}

func (r UserRepository) Rename(id uint64, name string) error {
    return r.Transaction(func(tx *database.DB) error {
        return tx.Model(&User{}).Where("id = ?", id).Update("name", name).Error
    })
}
